# ADR-4441-A: A player character stands as a persona group only on opt-in, and its profile cannot move during the standoff

A player character is a `Persona` like a named NPC, so it reuses ADR-4373-A's persona group: a GM stands the opted-in character as an opponent (`AddOpponentAction`, `persona_id`) and `open_standoff` makes it its own `StandoffGroup`. Consent is a row, `CharacterStandoffProfile.opted_in`, one per sheet; its drives (`CharacterDrive`, a `Property` that some `CreatureDrive` already carries, at a `DriveStrength`) and its `cause` (`CauseKind`) are the player's own picks from the catalogs creature templates use, with no free text. Four rules follow. (1) The gate is on the target, not the actor: `open_standoff` skips a player character who has not opted in, and read, press and terms refuse one (and refuse the character acting on itself) before any roll, so a group made some other way is still safe. (2) A player character is `is_player_character` minus the NPC shelf, because a story NPC a GM holds has a tenure too and is a named NPC that needs no consent (slice 3 keeps working). (3) The profile is read live and is locked while the character stands in a live standoff, opting out included: the same reason ADR-4373-A reads a persona live, and the lock is what keeps a live read from changing under a running standoff. It unlocks when the group settles, the fight begins or the encounter completes. (4) The pressing player still rolls; the profile only sets the grade, as a creature's drives do, through the same `social_target_difficulty` (ADR-4145-B). A player character's cause fires like any group's, so the opt-in covers a standoff that ends in a fight with that character in it; a GM-run scene still routes it to a proposal. We rejected stamping the profile on the opponent at spawn (ADR-4361-A), because the character outlives the encounter and a stamp could drift from a profile its player changed since. We rejected giving player characters a `CreatureTemplate`, because a template is shared authored content and a profile belongs to one player. We rejected making consent per pair of characters, because it needs a table of pairs and a prompt flow for a case the per-character switch answers.
