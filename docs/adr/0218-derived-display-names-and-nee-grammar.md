# ADR-0218: Derived display names; née replaces the birth particle; Arx abstains

**Status:** Accepted (2026-08-17, Apostate ruling — #3261)

Stored character names stay bare `First Family`; every particled form ("Queen
Sharlotte ne Regente dau Vaelmont") is a **derived view** composed at display
time and mirrored into Evennia aliases, never persisted as identity. A stored
particled name is a fact that goes stale on marriage, adoption, house
elevation, or a vocabulary retune; a derived one re-renders correctly for
free, and retuning a particle is a one-row data edit instead of a mass rename.
The née grammar is continental and **replacing**: `ne <BirthFamilyName>`,
bare — "ne du Regente" was rejected as clunky, so the née segment never
carries the birth particle. The taken-in particle covers *every* non-born
membership basis (married/adopted/legitimized/granted), widened from #3091's
married-only spouse form, because realms treat adoption and legitimization as
the same graft into the name (Ariwn's vampire making is literally adoption
under house law). Suffix particles were rejected outright — many house names
are plain English words ("Redcloudesh") — so all particles are prefixes, with
apostrophe-terminal forms attaching unspaced ("D'Regente"). **Arx abstains**:
it has no nobility, so it seeds no particle rows and a bare noble-style name
reads as Arx. Alternative rejected: baking the particled form into the stored
key/persona name (search "for free"), which still needed an alias layer for
particle-less matching and made every lifecycle event a rename.
