# ADR-4362: Pledge credits explain a pledge's favor and never count it

A pledge's progress is the favor the character earns with its being after pledging, kept on `Project.current_progress` (#4333 Ruling 9: favor is the only pledge progress). The approved design also has the player see every deed credited to the pledge with its calculation, so each favor write while a pledge is open writes a `PledgeCredit` row (`world.worship.models`): the base favor, the earning rate, the amount credited, and the resonance grant, offering or rite performance it came from; the closing and lapse awards are recorded the same way but add no progress. `bump_devotion` is the single place that writes both, so the counter and the rows cannot disagree, and the weekly deed cap reads the rows' base favor. We rejected deriving the card from the source ledgers at read time (`ResonanceGrant`, `CeremonyOffering`, `WorshipRitePerformance`, `Prayer`), because none of them stores the base favor before the earning rate or the rate applied, and the earning rate changes with modifiers; adding favor columns to each of those source tables, because it would scatter one pledge's history over five tables owned by other systems; and a separate pledge counter, which the one-currency ruling forbids.
