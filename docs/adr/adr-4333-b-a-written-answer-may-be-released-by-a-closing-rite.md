# ADR-4333-B: A vision written ahead may be released by a closing rite

A vision was "never automatic, never player-triggered" (#3779): rare because a person wrote each one when it was sent. A pledge to a being now ends in one: when a closing rite resolves a pledge, the system draws an `Answer` staff wrote ahead for that being and outcome tier and delivers it through `send_vision` as an ordinary `Vision` (with `Vision.answer` naming the row). A person still wrote every word, a player still cannot ask for one on demand (it takes a whole pledge, a favor target earned over game weeks and a closing rite), and below Success the answer carries no fact text and no fact clue, so hidden information still comes only from a successful check. The Vision glossary entry is amended to say so. We rejected routing every closing answer through a staff writing queue, because that is the on-demand surface the standing rulings exclude and it would stall every pledge on staff time; a separate "sign" or "omen" delivery beside Vision, because a second display and record for the same thing would split the one treatment reserved for visions; and generated text, because there is no LLM in gameplay and authored text only.
