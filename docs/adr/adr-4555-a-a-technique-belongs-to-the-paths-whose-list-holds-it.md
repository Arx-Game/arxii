# ADR-4555-A: A technique belongs to the Paths whose list holds it, and a Tradition's list restricts

A technique is the intersection of a Gift and a Path, but the code read the two grant lists as if Tradition techniques had no Path: character creation added a Tradition's own techniques to every member's pool on any Path, a Path crossing granted every technique on the new Path's list, and a cast added the caster's current Path's skill whatever Path the technique came from. We decided that the existing lists carry the Path side and only the reading changes. `PathGiftGrant.starter_techniques` means "the techniques for this Path and Gift": a technique is offered only on the Paths whose list holds it, and it belongs to those Paths for its cast skill. `TraditionGiftGrant.special_techniques` restricts: a technique no Tradition grant lists is open to every Tradition, and one listed by one or more is open only to those Traditions. One rule (`cg_catalog.tradition_listings` / `offered_to_tradition`) serves character creation's pool and gift list, Academy training eligibility and `grant_path_magic`. A cast adds the caster's current Path's skill when that Path is one of the technique's own, otherwise the skill of the technique's first own Path in Path order (stage, sort order, name, then pk); a technique on no Path's list keeps the caster's current Path. We rejected: a direct technique-to-Path foreign key, which existed once and was dropped as too strict (one technique can belong to several Paths); a new technique-to-Path model, when the Path grant list already says it; and keeping Tradition techniques Path-free, which let a Tradition teach a technique meant for one Path to members on any Path.

**Partly superseded (#5002, [ADR-5002](adr-5002-a-casting-style-carries-its-magic-skill.md)).** A technique no longer belongs to its Paths for its cast skill: a cast adds the skill of the casting style it is worked in, so `technique_paths`, `skill_path` and `Technique.cached_own_paths` are gone. The offering half (a technique is offered only on the Paths whose list holds it, and a Tradition's list restricts) stands.
