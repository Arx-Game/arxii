# ADR-4737: Rolled surges recur each round through a nullable repeat_round key

A taunt, a rally and a hurt ally can each surge the same player character round after round, but every older surge kind is once per encounter and `DramaticSurgeRecord` enforced that with unique constraints that already exist in production. We added a nullable `repeat_round` column that the three rolled kinds fill with the encounter's round number, kept the four older unique constraints and made them apply only where `repeat_round` is null, and added two new unique constraints for the rows where it is set (one per subject, one without a subject), so a rolled kind surges once per round per subject and the other kinds still surge once per encounter. The rejected alternatives were reusing the once-per-encounter constraints, which would let a rolled kind surge only once in the whole fight, and a separate table for rolled surges, which would split the one write path (`apply_dramatic_surge`) and the one round payload that read every surge from one place; the price is a nullable discriminator column with a check constraint keeping boss and companion subjects out of the rolled rows.
