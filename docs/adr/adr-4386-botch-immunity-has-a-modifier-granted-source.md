# ADR-4386: Botch immunity has a modifier-granted source that shares the one outcome floor

ADR-0152 made botch immunity a covenant vow perk, but the owner wants any character niche protected, not only a covenant role (ruling 2026-10-16). We decided botch immunity has a second source: a `ModifierTarget` in the `botch_immunity` category, scoped by exactly one of `target_check_category` or `target_scope_check_type`, which any modifier source can grant (a distinction, a condition, an achievement, an alternate form, a worn crafted item); a positive total raises a raw botch to the least-bad non-botch result by joining the same floor list the vow perks build in `_apply_outcome_guarantees`, on every rolled check, with no situation context needed. The adopted defaults are: a target names exactly one scope; the floor is not announced to the room, and only the roller (and staff) see a value-0 "Cannot botch: <source>" line on the roll's breakdown, which shows on any in-scope check of an immune roller, not only one whose botch it raised; and a raised botch is a Failure in every respect, so a consequence pool's Failure row applies. We rejected a separate floor function for the modifier route (two floors could disagree about the chart's least-bad outcome), changing `target_check_type` from one-to-one to a plain FK so the check-bonus target could carry the scope too (it would break the `check_type.modifier_target` accessor the check-bonus code reads), and scoping the immunity to a covenant role (vow perks already do that).
