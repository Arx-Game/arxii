# ADR-4248: A unit test is written as bug-fix evidence and retired on mutation evidence

A unit test is written in one case only, as the evidence of a bug fix that fails before the fix and passes after it; it is marked `@tag("regression")`, names its issue in its docstring, and stays. New work gets a journey for what a player does and a Hypothesis property for each rule, stated from a spec, a docstring or a ruling. An existing unit test is removed only when a mutation run (`just mutate`, `tools/mutation_run.py`, cosmic-ray 8.9.0 called through a pinned `uvx`) shows the kept tests catch every change it catches; where they do not, the property or journey is written first. This replaces the hand-confirmed ledger of ADR-3657 as the evidence for a removal: reading a test file did not settle what it guards, the `world.conditions` ledger kept 60 of 67 modules, and the unit suite grew from 31,546 to 33,466 tests after 23 removal tranches. The pilot measured it instead. In the Primum power curve, 11 of 69 changes were caught only by four unit tests; three properties written from the docstrings brought that to 0, the four tests were deleted, and the runs showed two behaviour-breaking changes that no test would have noticed, which the properties now catch. In four older `world.conditions` service functions the six conditions journey modules caught 23 of the 77 changes unit tests catch, and a hand-check of 30 of those unit tests found 28 whose expected values a docstring, a system doc, an ADR or an issue states. We rejected the loose rule (delete unit tests file by file and list what is left unguarded), because in the six piloted functions it would have raised unguarded changes from 38 to 92 of 142; a mutation score as a target or a required check, because one function takes 30 to 99 minutes on Postgres, so a run is never a CI job of any kind and is started locally (`--tier postgres`) by the session retiring those tests; and adding the tool to the project's dependencies, because they are one flat list the production image installs. A mutation run says whether a test notices a change, never whether it asserts the right value, and a surviving change that no written rule covers is a question for the maintainer.
