# ADR-4501-A: A cosmetic Mage Scar is a reward that never gates, and a trial never skips a prerequisite

A trial (#4343) gives a Success or Critical Success reward and a cost, and the two must not be confused. A Mage Scar queued with `ConsequenceEffect.scar_is_cosmetic` becomes a `PendingAlteration` with `is_cosmetic` set. It is still written by the player and seen by others, but it has no drawbacks (resolution requires every magnitude at 0, and a library pick must be a drawback-free entry), `has_pending_alterations` ignores it so `enforce_advancement_gate` never waits on it, and `create_pending_alteration` merges a scar only with one of the same `is_cosmetic`, so a reward never raises a cost's tier. A cosmetic scar is never a trial's cost: the save rule for a technique-opening consequence counts only a non-cosmetic scar or a condition on the actor. It is not tier 1 "Cosmetic Touch", which stays an ordinary tier that gates advancement. The outright grant of a technique is `learn_technique` with the new `TRIAL` origin, and unlike `GM_GRANT` that origin does not skip `enforce_technique_prerequisites`: only the training is waived, never a gate, so the gift, the other prerequisites and the technique cap still refuse it, and the refusal leaves the known codex entry, the cost and the reward in place. We rejected reusing tier 1 as the reward (it would keep holding advancement back), a trial-specific scar model (a second wheel beside `PendingAlteration`), and granting the technique with `GM_GRANT` (it would hand every authored trial the skip a GM award has).
