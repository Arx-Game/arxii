# ADR-4034: The web client renders no form for a telnet command

The server serializes each character's command set into descriptors (an action, a prompt template, a `params_schema`) and pushes them in the `commands` frame on puppet and on every command-set change. In August 2025 a "Quick Actions" panel (PRs #153, #154, #158 and #159: `CommandDrawer`, `CommandForm`, `CommandSelectField`, `CommandTextField`, `groupCommands`) built a form from each descriptor and sent the filled-in command text back; the client stored the descriptors as `session.commands`. The three-column game layout (commit `da839ab6d`, PR #285, 2026-02-13) deleted the panel that mounted `CommandDrawer`, and no later surface rendered the components or read `session.commands`. Meanwhile three other paths took over what a person does: the composer recognises a typed command from the frame's `names` (`Session.commandNames`, #4346), the persona menu (ADR-4030) builds the actions on a person, and the typed combat and battle panels declare their own actions. The maintainer ruled on 2026-11-20, after asking for the evidence of why the palette existed and what replaced it, that the web client retires it.

**Decision.** The web client does not render forms for telnet commands. Actions, the persona menu and the typed panels are the web path to acting; the composer is the path for typing. The four components, `groupCommands`, `formatCommand`, the `CommandSpec` and `ParamSchema` types, `Session.commands` and the descriptor half of `handleCommandPayload` are removed. The `commands` frame is unchanged on the wire, and the client reads only its `names`.

**Consequences.** Nothing a player can reach changes, because nothing rendered the palette. The server still builds and sends per-command descriptors (`serialize_cmdset`, `ArxCommand.to_payload`, `FrontendMetadataMixin`, `CmdPage`'s web form metadata); the client simply stops storing them. Whether that server half also goes is a separate decision. A later feature that wants a form for a command starts from an action with a declared schema, as the persona menu and combat panels do, not from a revived descriptor palette. The git history before #4034 holds the removed components.

**Rejected:** finishing the palette (a second path to every action beside the persona menu and the typed panels, built on descriptors that exist for telnet commands and were never shaped for a web UX); and retiring the server pipeline in the same change (it also carries the `names` the composer reads, and removing the descriptor half is a server-side question with its own callers and tests).
