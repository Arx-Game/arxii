# ADR-4450: A roll adds skill terms at call time while its check type stays the base

Magical rolls need to include skills that staff choose (a Path's technique skill, a skill per kind of ritual or resist), but a check's skills came only from the rows on its `CheckType`, and a per-character cast check already existed to carry the caster's own stat and skill. We decided that a roll may add skills when it is made: `perform_check` and its siblings take a keyword-only `extra_traits` of `ExtraTraitTerm(trait, weight)`, scored like extra `CheckTypeTrait` rows, developed once per trait per roll, and counted among the roll's involved traits for capability and thread matching; the magic layer builds the terms from `MagicActivitySkill` rows and the Path, Gift and technique skill fields (`world/magic/services/magic_skills.py`), so no skill is named in code. This amends ADR-0182 (a check's skills are no longer only the check type's rows, though a `stat_override` still replaces only the STAT row) and ADR-0096 (the caster's personal check still wins and the template check is still the fallback, but `resolve_cast_check` returns that check type together with the technique skill term, replacing `resolve_cast_check_type`). We rejected synthesizing a check type per character and skill, as the personal cast check does for one stat and skill: it needs a row per sheet and skill that must be rebuilt whenever a Path, mapping or skill changes, and it spreads magic skills across dozens of check types that staff would have to keep in step.


**Amendment (#4547).** The skills these terms carry are Magic-category skills only: the four pickers (`MagicActivitySkill.skill`, `Path.technique_skill`, `Gift.technique_skill`, `Technique.skill`) share `limit_choices_to=MAGIC_SKILL_CHOICES` (`world/magic/skill_choices.py`), so a skill a character picks elsewhere can never reach a magic roll slot, and no seeder names, creates or weights a skill for magic. A check type that weights a Magic skill itself would count it twice, so the Required content dashboard lists those for staff to repoint; production rows were left as they are rather than migrated.
