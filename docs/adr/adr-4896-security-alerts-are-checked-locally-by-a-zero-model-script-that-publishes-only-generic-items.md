# ADR-4896: Security alerts are checked locally by a zero-model script that publishes only generic items

Dependabot opens the first fix attempt, but an open or merged PR does not prove an alert is fixed, and alert detail in a public repository is a route to the weakness. We run a deterministic script (`tools/security_monitor.py`) from the maintainer's own operating-system scheduler every 4 hours, inside the authenticated development container, and it starts a local agent only when an alert is new, reopened, changed, due for escalation or due a daily retry. Every public write is built from the alert number alone (a generic tracking issue with a marker and a link only maintainers can open), alert age counts from original detection, and only a fresh read showing `fixed` closes an item; a dismissal never does. We rejected a GitHub Actions workflow because it would need a token able to read alerts, its logs and summaries are a public surface, and a workflow token cannot be trusted to start an agent; and we rejected a scheduled Codex automation as the check because it starts a model run on every tick. The cost is that coverage stops while the maintainer's machine is off, with no independent watchdog and no fast trigger (GitHub Actions has no Dependabot alert event), so the script reports a gap on its first run back and `status` fails when no check succeeded recently.
