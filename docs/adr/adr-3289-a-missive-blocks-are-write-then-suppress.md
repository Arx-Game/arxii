# A missive block is write-then-suppress, and attachments on a blocked missive stay held

A missive is addressed by persona, so nothing a sender can see may point at the player behind a mask. When a block sits between the two players, `send_missive` writes the missive like any other and flags it `undeliverable`: the sender gets the same "on its way" confirmation and is never told, the recipient never sees the letter, and the block is checked again at arrival (the sweep and read time) so one placed while the letter travelled still holds. Coin and items on it stay pending in custody and are never auto-returned, because a return is an observable event the sender could read as "that persona blocked me". We rejected refusing the send up front ("you cannot write to that person"), because the refusal itself fingerprints the mask's owner; the cost accepted is that goods sent into a block stay held until staff step in, and the way out, if that proves too costly, is a return that reads the same for every undeliverable cause. Complements ADR-0226 (IC missives are a persona-authored system separate from `PlayerMail`).
