# ADR-5072: An approved spec ships as one PR, and slices are only for parallel builds

An approved spec used to be built as a chain of `Slice N of #M` child issues, one PR each, built one after another; the maintainer ruled against that on #5018 and #5066 because sequential slice PRs slow velocity and buy nothing, since each waits on the last anyway. We decided an approved spec ships as one PR that closes its issue: the spec's numbered Scope items are build order inside that PR, a decided extension is built in it, and a gate inside the work (a demo approved before one part is built, a design question put to the maintainer) is a pause in the same PR, not a split. Slices are used only when parts can be built in parallel, on independent files with no part needing another's output, and then the ADR-4447-A machinery (`Slice N of #M`, parent approval through `validate-discovery.sh`) applies unchanged. We rejected keeping slices as the default for smaller reviewable PRs, because the maintainer prefers large bodies of work kept robust by our testing (2026-05-25: "I'd like our PRs to be fairly beefy").
