# ADR-4413-A: The reveal rule reads for the character you are on, never for the account

Whether a viewer sees who is behind a mask (`world/scenes/persona_display.py`: `build_persona_display_map`, `resolve_display_for_viewer`, `identity_revealed_to_viewer`) is decided for one `CharacterSheet`, the character doing the looking: its own faces render real, its own `PersonaDiscovery` rows reveal, and its own `disguise_sight` levers (#4396, `pierced_disguise_kinds(viewer_sheet)`) pierce. On telnet that sheet is the puppet's or actor's `character_sheet`; on the web it is the account's durable selection (`world.relationships.reads.resolve_viewer_sheet`, kept in step with the puppet by login and `@ic`, read off `Account.cached_selected_entry` so it costs one query per account per process), and a request that plays nobody reads as a stranger. Staff stay universal discoverers (#1279). The owner ruled it on 2026-10-17 when #4396 put sight on the same footing as discovery: there is no out-of-character reason for a reveal to spread across an account's characters, and a character-scoped read is a good reminder that the character you are on does not know this and should not act as if they do; it is the same rule the secrets tab already follows (#1334, "IC reads scope to the active character"). We rejected keeping the account-wide set (`viewer_context_for_account`, every sheet the account plays, a union of their personas and discoveries), which had been the rule since #1109 and let a player on Hobb read a stranger Maud had unmasked. We rejected a per-request `viewer` query parameter for the feed and the sheet, because the durable selection already answers "who am I acting as" for every other web read (#3412, #3957) and the frontend mirrors it; a parameter would be a second source of the same fact. The feed's other account-wide reads (language comprehension, a private pose's content to its own writer, a dramatic-moment tag on one's own sheet) are out of character or ownership questions and keep the account's sheets.
