Findings across all three passes, all now resolved:
  1. **Screen 3b (unknown outcome, Check status/Retry) was unreachable** — the reconnect-reconciliation effect nulled `pendingSpeechRef.current` before `markUnknown()` could fire, so the state immediately resolved to the stranded banner instead. Fixed (commit `cac04fe3b`): the ref is now retired only at the two genuine resolution points. Re-verified live: drop the socket mid-send, reconnect, and the "Connection dropped before we heard back. We don't know if this sent." banner with Check status/Retry now renders exactly per the demo.
  2. **Two of the branch's own four Playwright journeys failed against the production build** because the mocked WS layer didn't replay `room_state` on the mocked `@ic` reconnect command; real Evennia's `at_post_puppet` hook (`src/typeclasses/characters.py`) unconditionally sends `room_state` on every puppet, confirming this was a fixture gap, not an app bug. Fixed (commit `2d569e5e4`); all 4 journeys in `frontend/e2e/narrative-play-delivery.spec.ts` now pass, run most recently as part of this report's own verification.
  3. **Screen 7's action-attachment acknowledged/pending badge was unbuilt**, then built as two adjacent elements instead of the demo's one combined pill. Fixed in two rounds (commits `7d9c35f9f`, `999a977ee`): the status indicator now nests inside the same detach button as the action name, reading as one grouped pill (`⚡ Perception check · ⟳ pending ✕` → `⚡ Perception check · ✓ acknowledged ✕`). Accepted, explainable divergence from the demo's exact iconography: the pill reuses the composer's pre-existing detach-chip grammar (predates this issue) rather than redesigning it to the demo's plain read-only badge — the demo's own masthead states composer chrome outside this issue's states is unchanged/out of scope, and the core requirement (one grouped pill, not two disjoint elements) is met.
  4. **The stranded-draft banner (Screen 4) leaked a raw internal storage key** (`account:1:Tehom:room:2`) instead of a human-readable place name, in the default room-pose composer state (no mode-switch active — the same state demo Screen 1 itself shows). Fixed (commit `9231c5b0b`): `roomName` (already computed by `GamePage.tsx` as `sceneData?.name ?? roomData?.name ?? 'Room'`) is now threaded through `GameWindow.tsx` to `CommandInput.tsx`, and the `strandedContext` fallback chain no longer includes `draftScope` at all. Re-verified live (screenshot `4-stranded-draft.png`): the banner now reads "Unsent draft from the Gilded Hart. This never got a response last time."
  5. **Screen 6's "Reconnecting → Reconciling → Ready" banner text has no distinct visible UI counterpart.** This is a ratified, intentional divergence, not a gap: the issue's own posted spec, Decision 6, states "Reconnect correctness, not reconnect cadence, is this issue's job... This issue's contract must stay unobtrusive at that cadence" — citing #3745, an open bug where the client force-relogs roughly every 127 seconds. A visible spinner banner firing that often would be the opposite of unobtrusive. The composer's actual behavior (Send disabled via the `ready` prop, typing still allowed, no banner) is the quieter, ratified alternative; screenshot `6-reconnecting.png` shows this state.
