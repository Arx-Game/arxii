## Unresolved findings

- **[Severe] The Look dialog still self-closes — not in the general case the fix and its regression test cover, but deterministically (10/10) in the exact condition the demo's own walkthrough uses.** Screen 1 shows the menu for a "quiet room, no scene" target, and that SAME menu is what Screen 2 opens Look from. Bisecting the trigger precisely (by content, not by guessing): a menu with the single-item, single-group shape `frontend/e2e/persona-menu.spec.ts`'s fixture uses (`groups: [{ key: 'perception', empty_state: '' }]`) never reproduces the self-close, at any item count, with or without the disabled "Identify" item's native `title` tooltip. Add back a non-empty group `empty_state` (the "Scene actions ... show here once a scene is running." footer line `src/actions/persona_menu.py:126-130` produces for any look-available, non-self target with no shared scene) and the Look dialog is present in the DOM at the instant of the click and gone by the very next sample 20ms later, 100% of the time across repeated trials — independent of persona identity, independent of masking (reproduces identically for a masked target given the same footer shape), independent of item count otherwise. `LookDialog`'s `Dialog.Root` is still `modal={false}` (`frontend/src/game/persona-menu/LookDialog.tsx:50`), still opened synchronously from a menu item's `onClick`, and `PersonaMenu.tsx`'s `onCloseAutoFocus={(e) => e.preventDefault()}` fix (lines 639, 650) still applies — but something about the closing menu's own footer `<div>` (a plain, non-`role=menuitem` trailing child, `PersonaMenu.tsx:596-608`) changes the timing or target of the dismiss-layer interaction the fix was meant to suppress, in a way the fix's own regression spec cannot see because that spec's fixture never has a footer. This is not a narrower or new bug than the one the first pass reported — it is the SAME bug, still open, for the majority real-world condition (no active scene), just no longer visible under the specific fixture the regression test happens to use. Suggested mechanical companion: extend `frontend/e2e/persona-menu.spec.ts`'s fixture to include a non-empty group `empty_state` (i.e. the actual shape `src/actions/persona_menu.py` returns whenever `scene is None`) in at least one of its two test cases, so the regression guard exercises the shape a real no-scene Look actually uses, not the easier shape that happens to work.
- **[Minor] Screen 1b's persona-menu header never shows the "(you)" suffix the demo specifies** ("Ysolde (you)"). `frontend/src/scenes/components/PersonaMenu.tsx:559` renders bare `{personaName}`; the app's "you" tag exists only on the room-sidebar row (`frontend/src/game/components/room-panel/CharactersList.tsx`), a different component from this popup menu's own header. The first-pass report (91caf75ae) incorrectly marked this checklist row `MATCH`; this pass corrects it after a fresh, careful re-render and crop-level comparison. Pre-existing, not touched by this fix wave.

## Investigated and disproven (recorded so it is not re-investigated)

A distinct hypothesis was tested during bisection of the Severe finding above: that switching the persona-menu's target between two DIFFERENT personas (right-click A, dismiss, right-click B, dismiss, right-click A again, choose Look) reproduces a self-close independent of the footer. An early throwaway test suggested this (3/8 pass rate), but re-testing in a clean, brace-balanced, byte-verified isolated file reproduced NO failures in 10/10 runs. The original signal traced to a malformed intermediate test file produced during bisection (an unclosed `test.describe` block, confirmed by a brace-depth check), not to the application. This path is not reported as a finding.
