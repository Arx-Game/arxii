## Unresolved findings

- weapon-chip-order-stable: the Strike weapon chips have no defined order, so the Rapier the demo draws first and selected stops being first once it is used. strike_weapon_options (src/world/combat/services/declarations/strike.py) builds the list by iterating character.equipped_items, and that query (src/world/items/handlers.py, EquippedItem.objects.filter(character_id=...) with no order_by, EquippedItem has no Meta.ordering) returns rows in database order. A Strike hit decrements the Rapier durability, the Rapier row moves, and the next encounter payload lists Throwing knives first; StrikeControl then defaults the pick to weapons[0], so a player who clicks Strike without looking strikes with the knives. Recorded: Rapier, Throwing knives, bare hands before the first hit; Throwing knives, Rapier, bare hands after it (finding-default-weapon-flips-desktop-dark.png). Fix: give the list a stable order (for example sort the options by the equipped body region and layer, or order the handler query by EquippedItem pk) so the first equipped weapon keeps its place. Mechanical companion: a Strike journey that equips two weapons, calls decrement_item_durability on the first, and asserts the strike_weapons list from /api/combat/ keeps the same order.
