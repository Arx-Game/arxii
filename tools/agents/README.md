# Reviewer Agents

Project-specific subagent definitions (`.claude/agents/*.md` frontmatter format),
symlinked into `~/.claude/agents/` by `.devcontainer/post-create.sh`. `.claude/`
is gitignored, so `tools/agents/` is the tracked home — same arrangement as
`tools/skills/`.

## When to add one

**Every defect that reaches `main` or production gets a reviewer agent for its
class, in the same PR as the fix.** Not a follow-up issue, not a line in a doc
nobody reads at the right moment: an agent that can be dispatched at the moment
the mistake would be repeated.

The test for whether a defect qualifies is not severity, it is *recurrence
shape* — could a competent agent make this same mistake again next week while
following the rules as written? If yes, the rules as written are the problem,
and a reviewer that reads the actual diff is the fix.

An entry here should carry, concretely:

- **the failure it exists to catch**, with the real error text, so it is
  recognizable rather than abstract;
- **why the existing gates missed it** — a defect that CI could have caught
  wants a test, not an agent;
- **what to check**, as things to look for in a diff, not principles to hold.

Pair it with a mechanical check where one is possible: the agent catches the
shape, the linter catches the instance. `reviewing-migrations` (skill) +
`tools/lint_migration_ddl_dml.py` (hook) + `migration-reviewer` (agent) is the
worked example.

## Current agents

|---|---|---|
| `implementation-quality-reviewer` | The diff has an explicit uncovered maintainability, security, privacy/RP, performance/operability, or contract lens and no narrower reviewer owns that recurrence shape. Dispatch with the selected lens; never use it as a generic council. | A workflow gap: the repository had narrow recurrence-specific reviewers and a Polytoken-only broad reviewer, but no tracked Claude contract for explicitly reviewing uncovered quality risks. |
| `evidence-challenge-reviewer` | Runs on every PR from `.github/workflows/evidence-challenge.yml` (Haiku 5.5, advisory, up to three rounds; ADR-4246). Dispatch it locally before opening a PR when you want the challenge early. One of two Haiku agents (with `guaranteed-outcome-reviewer` and `design-prereview-reviewer`): it judges evidence, which needs skepticism more than depth. | Three migrations passed CI and failed on the production deploy because CI migrates an empty database: `0220_upbringings` (`cannot ALTER TABLE "arxii_origintemplate" because it has pending trigger events`, 2026-09-04), the `0149` constraint (2026-09-24) and the `0170` re-level (2026-10-03). Agents claimed production-copy tests they had not run, and #3660 shipped past nineteen green tests. Research (arXiv 2610.11835) found 8-17% of LLM-written regression tests enforce the fault. Mechanical half: `open-pr.sh` refuses a PR without a `PR_VERIFICATION` report. |
| `bypassed-writer-reviewer` | A diff assigns a field or attribute directly (`obj.home = room`, `sheet.x = y`, a row `update()`) where a service function owns that write and carries side effects (a recompute, a cache clear, a derived row, a notification), and when reviewing one. | `finalize_character` set `character.home` directly before granting the residence tenancy, so `maybe_default_residence` saw a chosen home and never called `set_residence`, the one recompute of the residence comfort AP-regen modifier (#1514): every character created since #2036 started without it, found only when #4394's live pass read the modifier back (#4404). No test had asked for the derived row. |
| `double-counted-modifier-reviewer` | A diff feeds a gathered modifier total into a check roll (`extra_modifiers=breakdown.total`), adds a term to `_compute_check_breakdown`, or adds a `ModifierSourceKind`, and when reviewing one. | Every check rolled through the modifier seam counted authored capability points twice, because the aggregator recorded them as provenance and its `.total` was fed in while `perform_check` added them again (#4453). |

Zero ticks were ever logged. |

Nineteen tests passed; a human found it on production. |
| `server-close-intent-reviewer` | A diff adds or changes a command or service that disconnects a session (quit, boot, ban, a logout, an idle or duplicate-login rule), or changes the close handler or reconnect policy in `useGameSocket.ts`. | `fragment-as-page-reviewer` | A diff adds a link (an href, an admin object tool, a redirect, a URL in a message) to a view that renders a partial template, or adds such a partial view, and when reviewing either. | A change form's "Open in Authoring Workbench" object tool linked straight to the editor fragment (`/admin/_authoring/editor/`), which the dashboard normally swaps into its panel.
